# Contributing

Start with [the architecture](docs/architecture.md) and the
[development plan](llm-foundry-development-plan.md). Use a focused issue and pull
request for each work package. Describe the user-visible problem, exact contract,
files, dependencies, tests, acceptance command, benchmark effect, and rollback.

## Development checks

```sh
git submodule update --init --recursive
cmake --preset release
cmake --build --preset release
ctest --preset release
cmake --preset sanitize
cmake --build --preset sanitize
ctest --preset sanitize
python3 scripts/check_repository.py
```

Use `FOUNDRY_TEST_MODEL` for the optional real SmolLM2 tests. Keep local weights,
Ollama metadata, private prompts, benchmark runs, and generated output outside Git.
Synthetic fixtures are generated by tests and require no downloads.

Use C17 for the core, CLI, and all GUI application files. Upstream API calls belong
in the C++ backend adapter. Preserve exception containment, ownership, cancellation,
main-thread GTK access, and the bounded event queue. Add meaningful tests for
changed failure modes; do not add a fake model backend as evidence of real inference.
Format original C/C++ code with `clang-format -i` and the repository's configuration
(the initial formatting pass used clang-format 23.1.0). Do not reformat vendored code.

Keep backend upgrades separate from feature/performance changes. Update the
submodule pointer and `docs/backend-revision.txt` together, rebuild, and rerun
compatibility, tokenizer/template, and performance checks. Do not change a
compatibility row to tested without recorded evidence.

Before a pull request, run `git diff --check` and inspect the staged file list.
Document API changes, effective configuration changes, timing definitions, and
new limitations. No benchmark claim should rely on a single run. See
[benchmark methodology](docs/benchmarking.md) and [release gates](docs/releasing.md).

GitHub CI uses the upstream [checkout](https://github.com/actions/checkout) and
[artifact upload](https://github.com/actions/upload-artifact) actions. It compiles
on macOS and Ubuntu and tests only synthetic fixtures unless a separately managed
integration environment supplies licensed local models. Workflow source is not
evidence that a hosted CI run has completed.
